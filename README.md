# Before the Answer

《Before the Answer》是一個展場互動作品。觀眾一進場會被掃描成一個「語言模型」，接到上一位觀眾留下的問題，然後親手做完 AI 回答前的每一步：切字、找位置、抽下一個詞、讓答案一個詞一個詞長出來。最後會看到自己做出的回答，以及完整的路徑紀錄。

這是單機、單頁的網頁原型。它不執行真的語言模型，也不連網路。題目、切字、星空位置、機率和答案都是預先準備好的資料，可以在後台換題。站 0 的攝影機只在本機辨識臉部節點，不拍照、不上傳。

## 快速開始

需要 Node.js `>=20.19.0`（開發時用的是 Node.js 24、npm 11）。

```bash
npm install
npm run dev
```

終端機會印出網址，通常是下面這些：

| 頁面 | 網址 |
| --- | --- |
| 展場 | `http://localhost:5173/` |
| 後台（換題、改每一站） | `http://localhost:5173/?admin` |
| 展場（強制 2D 畫面） | `http://localhost:5173/?renderer=2d` |

在展場頁面按 `D` 會打開演示工具，最下面也有「開啟後台」按鈕。

正式展出時用打包版：

```bash
npm run build
npm run preview
```

攝影機只能在 `localhost` 或 https 下開啟。請在展示電腦本機開網頁，不要用區網 IP。

## 體驗流程

預設題目是「為什麼人會想念一個人？」。

- 每一站開始和結束都有一張黑幕字卡，說明這一站要做什麼、剛完成什麼，以及目前在第幾站。字卡會自己消失，也可以按任意鍵或點一下跳過。
- 每一站右上角有任務卡，列出操作步驟，完成後顯示一句「你剛剛學到」。
- 目前用鍵盤和滑鼠代替實體裝置。

| 站 | 名稱 | 觀眾做什麼 | 操作 |
| --- | --- | --- | --- |
| 0 | 入口 | 站到鏡頭前，被掃描成節點影像並拿到模型編號，再點開裝著上一位觀眾問題的彈珠。 | 「開始掃描」或「不掃描、用預設影像」，再點彈珠 |
| 1 | 切字 | 問題被拋到空中，像切西瓜一樣揮刀劈開。只有劈在 tokenizer 的切縫上才會裂開，劈在字中間會彈開。切下的字片翻面變成編號，兩個「人」是同一個編號。 | 按住滑鼠劃過句子，或按 `Space` 切下一刀 |
| 2 | 向量 | 轉動星空，把目標字轉進中間的光帶後鎖定。鎖定的字會連到離它最近的 3 個字，這些字之後會出現在答案裡（線索袋）。 | `←` `→` 或拖曳轉動，`Space` 鎖定 |
| 3 | 接龍 | 機率轉盤的每一格是一個「下一個詞」的候選，格子越大機率越高。抽到答案的詞就接上去；抽錯了，下一次改成直接選機率最高的詞。右側會標出這個詞是「因為注意到」問題裡的哪個字。 | `Space` 或「轉！」 |
| 4 | 生成 | 答案開頭是站 3 抽出的詞。每壓一下水泵就冒一個水泡，水泡破掉答案就長一塊；停手，生成也會停住。 | `Space` 或 `↓` |
| 5 | 輸出 | 看完整答案，再進入回顧收據，看這次鎖定的字、抽到的詞和壓泵次數。 | 「查看這次的路徑」 |

## 後台：換一題

打開 `http://localhost:5173/?admin`。

1. 填入「上一位觀眾的問題」和答案，選好切字方式，按「自動切字」。
   - 「以詞為單位」比較好讀。
   - 「真實 GPT-4o tokenizer（o200k）」是真正的切法，中文常常一個字切成一塊。
   - 也可以用「|」手動調整切點。
2. 按「產生每一站」，系統會自動排好下面這些內容：
   - 站 1：每一塊的編號。單一 token 用真實的 o200k 編號；由多個 token 組成的詞，用固定的示意編號。
   - 站 2：要鎖定的字、星空位置和線索字。可以按「重新排星空」重排。
   - 站 3：要轉幾輪，以及每一輪的候選詞、機率和「因為注意到」。黃底那格是答案真正的下一個詞，不能刪。存檔時，機率會自動調成加起來 100%。
   - 站 4、5：答案。
3. 每一站都可以再手動修改。改完按「儲存並套用到展場」，再把展場頁面重新整理，就會換成新題目。
4. 「匯出 JSON」可以備份，「匯入 JSON」可以載回，「恢復預設題目」會回到預設題。

題目存在這台電腦瀏覽器的 localStorage 裡。換電腦或換瀏覽器時，請用匯出、匯入把題目搬過去。答案目前要手動輸入，不會自動生成。

## 演示工具

在展場頁面按 `D` 打開。可以：

- 跳到任一站。跳到後段時，會自動補上前面幾站的結果，回顧頁會標示「演示預設路徑」。
- 重播這一站，或重新開始。
- 切換畫面品質 Low／Medium／High，開關「減少動態」。
- 開啟後台。

## 網址參數

| 參數 | 作用 |
| --- | --- |
| `?admin` 或 `#admin` | 開後台 |
| `?renderer=2d` | 強制用 2D 畫面（WebGL 不能用時也會自動切換） |
| `?cards=off` / `?cards=on` | 關閉或強制開啟黑幕字卡（自動化測試預設是關閉的） |

## 隱私與離線

- 臉部模型放在 `public/models/face_landmarker.task`，已經包含在專案裡。
- MediaPipe 的 WASM 檔會在 `npm run dev` / `npm run build` 之前，自動從 `node_modules` 複製到 `public/mediapipe/wasm`。所以換電腦後要先跑一次 `npm install`。
- 掃描只保留臉部節點座標，掃描完就關鏡頭。重新開始時，節點資料會刪除。
- `index.html` 的 CSP 設定是 `connect-src 'self'`，頁面只能連到本機。這也擋掉了 MediaPipe 內建送往 Google 的使用紀錄。

## 專案結構

```
src/
  app/          狀態機（experienceReducer）、場景順序、selectors
  scenes/       每一站的畫面：Input、Tokenization、Vector、Prediction（站 3）、Generation、Output、Summary
  components/   任務卡、黑幕字卡、進度帶、演示工具、線索袋等共用元件
  data/         題目資料與規則
    scenario.json        預設題目（問題、token、星空、轉盤、答案）
    scenarioStore.ts     讀取後台存的題目，沒有就用預設題目
    validateScenario.ts  檢查題目資料
    tokenCuts.ts         站 1 切縫判定
    vectorSpace.ts       站 2 星空投影、光帶對準、最近鄰
    clues.ts             線索袋
    prediction.ts        站 3 轉盤抽詞、扇形角度、停點
    stationCards.ts      黑幕字卡的文字
  admin/        後台頁面、自動產生每一站、tokenizer
  input/        攝影機掃描、音效
  motion/       換場動畫
  visual/       背景粒子、WebGL 與 2D 畫面
  styles/       版面與動畫樣式
e2e/            Playwright 瀏覽器流程測試
src/tests/      Vitest 單元測試
```

常改的地方：

- 字卡文字：`src/data/stationCards.ts`
- 每一站任務卡的文字：各站 `src/scenes/*Scene.tsx` 裡的 `MissionCard`
- 粒子數量、水泡速度、換場秒數：`src/visual/visualConfig.ts`
- 版面和顏色：`src/styles/stage.css`

`answer.tokens` 開頭的空白是組句子用的，請不要刪掉。

## 測試

```bash
npm run typecheck   # TypeScript 型別檢查
npm run lint        # ESLint
npm test            # 單元測試
npm run build       # 打包
npm run test:e2e    # 瀏覽器流程測試（Playwright）
```

第一次跑瀏覽器測試時，如果電腦裡沒有 Chromium，先執行 `npx playwright install chromium`。

## 這不是真的 AI

畫面上的星空位置、連線、機率和答案，都是事先設計好的示意資料，用來說明概念。它們不是真的 embedding、attention、logits 或模型推理。粒子數量不代表參數量或算力，生成的速度也不代表模型的速度。唯一真實的部分，是後台可以選用的 o200k tokenizer 切法和編號。
